# 2026.10.29 TIL

# Git

1. git checkout -b 브런치 이름~
* -b 브런치 생성하고 해당 브런치로 스위치
2. --graph
* git log --oneline --all --graph 터미널내에 그래프로 브랜치 표시
3. merge
* git merge feature/shop   : main 으로 feature/shop을 병합시킴
4. 충돌
* push 입력 실행시 먼저 push 돼있는건이 있으면 오류 발생, pull 먼저 실행후 push 진행
* pull 후에 같은 동일라인이 수정되어있으면 두가지를 같이 보여주니 그중 올바른걸 남겨 수정 후 다새 재차 add.,commit, push를 진행해 충돌을 수정한다.
5. 3-way merge
* 브랜치에 각각 신규 커밋이 1회 이상 있는 경우 merge 명령을 내리면 두 브랜치의 코드를 합쳐 새로운 커밋을 자동으로 생성해줌
    * 이걸 3-way merget라 부르고 , git merge + 브랜치명 했을 때의 기본 동작 방식
6. fast-forward merge 
* 가끔 새오운 브랜치에만 커밋이 있고 메인 브랜치 , 혹은  기준 브랜치에 신규 커밋이 없을 때가 있음.
* 이 경우 merge 명령을  내리면 fast-forward merge 했다고 알려준다
7. 브랜치를 삭제하려면
* git branch -d 브랜치명
* git branch -D 브랜치이름
    - 이러면 필요없는 브랜치를 삭제할 수 있다.
    - merge가 완료된 브랜치 삭제 시엔 -d 이것만 해도 되지만 merge 없이 그냥 브랜치를 삭제하려면 -D 해아한다
8. rebase and merge
* rebase는 브랜치의 시작점을 다른 커밋으로 옮겨주는것
* fast-forward merge 하는것
9. 사용이유
* 3-way merge 말고 강제로 fast-forward 하고 싶을 때
* 커밋 내역을 한 줄로 계속 이어서 남기고 싶을 때
    - 그럴때는 3-way merge 대신 rebase ans merge 사용해도 된다.
10. rebase를 사용하려면 
* 새로운 브랜치로 이동
* git rebase main 
* 브랜치가 메인 브랜치 끝으로 이동되면 fast-forward merge 하면 된다
    - 단점 충돌이 많이  발생한다.
11. squash ans merge
* 3-way merge랑 다른점 새 브랜치에 있던 커밋들이 메인 브랜치로 이동된다.
    - 결과는 같지만 하나는 3-way merge는 선으로 연결되지만, squash 는 연결없이 바로 메인으로 이동된다.
