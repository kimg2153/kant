## Compose 파일 만들기

- docker-compose.yml 

> name: sportscenter <br>
services:<br>
  db:<br>
    container_name: sportscenter-db
    image: postgres:18<br>
    environment:<br>
      POSTGRES_PASSWORD: postgres<br>
    ports:<br>
      - "5432:5432"<br>
    volumes:<br>
      - pgdata:/var/lib/postgresql<br>
volumes:<br>
  pgdata:<br>

| 줄 | 뜻 |
|---|---|
| name: sportscenter | 이 Compose 프로젝트의 이름. 네트워크·볼륨·컨테이너 이름 앞에 붙습니다(소문자로 씁니다) |
| services: → db: | 실행할 컨테이너 목록. 이 컨테이너를 db라는 이름으로 부릅니다 |
| container_name | 컨테이너 이름을 sportscenter-db로 고정합니다. Docker Desktop 목록과 docker ps에 이 이름이 보입니다 |
| image: postgres:18 |	PostgreSQL 18 공식 이미지 |
| POSTGRES_PASSWORD | 관리자 계정(postgres)의 비밀번호. 빠뜨리면 컨테이너가 바로 종료됩니다 |
| "5432:5432" | 내 컴퓨터 포트 : 컨테이너 포트. DBeaver 같은 프로그램이 접속할 때 씁니다 |
| pgdata:/var/lib/postgresql | 데이터를 볼륨 pgdata에 저장합니다. 컨테이너를 지웠다 다시 만들어도 데이터가 남습니다 |
| 맨 아래 volumes: | pgdata라는 볼륨을 쓰겠다는 선언 | 


## 컨테이너 실행

> docker compose up -d

| 부분 | 뜻 |
|---|---|
| up | 파일에 적힌 컨테이너를 만들고 실행 |
| -d | 백그라운드에서 실행하고 터미널을 바로 돌려줌 |

## 상태 확인

> docker compose ps

- 무언가 이상하면 컨테이너가 남긴 기록(로그)을 봅니다. 마지막 부분에 database system is ready to accept connections가 보이면 접속 준비가 끝난 상태입니다.

> docker compose logs db

- 볼륨은 어디에 생겼을까? SportsCenter 폴더를 열어 보면 docker-compose.yml 하나뿐입니다. 정상입니다. 이름 있는 볼륨은 프로젝트 폴더가 아니라 Docker가 관리하는 저장 공간에 만들어집니다.

> docker volume ls

-다른 실습에서 만든 볼륨이 있으면 목록에 함께 나옵니다. docker volume inspect sportscenter_pgdata를 실행하면 Mountpoint 항목에 실제 저장 경로가 나오지만, Docker Desktop(macOS·Windows)에서는 Docker 가상 머신 안의 경로라 Finder나 탐색기로 열 수 없습니다. 용량은 Docker Desktop 앱의 Volumes 메뉴에서 확인합니다.
