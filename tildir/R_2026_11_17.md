## 테이블 간 관계와 ERD 읽기
- 회원과 사물함은 1:1, 종목과 강좌는 1:N, 회원과 강좌는 N:M입니다. 관계 종류마다 막아야 할 것이 다르고, 그 차이가 CREATE TABLE의 한두 단어로 드러납니다. 오늘 만든 테이블로 체육관 ERD를 완성해 읽어 봅니다.

> 오늘의 목표 <br>
1:1 관계를 FK + UNIQUE로 만들고, ON DELETE CASCADE가 어떻게 동작하는지 확인한다.<br>
N:M 관계를 중간 테이블과 복합 PK로 만든다.<br>
까마귀발 표기 ERD를 보고 관계와 선택/필수를 읽는다.<br>


- 회원 1명은 사물함을 최대 1개만 배정받습니다. 배정 기록에 회원 번호(FK)를 적되, 같은 회원 번호가 두 번 나오지 못하게 UNIQUE를 붙이면 1:1이 됩니다. 회원이 탈퇴하면 배정 기록도 함께 지워지도록 ON DELETE CASCADE를 붙입니다.

``` sql
CREATE TABLE lockers
(
    locker_no       INT     PRIMARY KEY,
    member_id       INT     NOT NULL UNIQUE REFERENCES  members (memeber_id) ON DELETE CASCADE,
    assign          DATE    NOT NULL 
); 

INSERT INTO lockers (locker_no, member_id, assign)
VALUES (101, 1, '2026-09-01');
```

- ON DELETE CASCADE 부모 테이블의 데이터가 삭제되면 참조하는 자식 테이블의 데이터도 삭제


## N:M 수강신청 테이블

- 회원 한 명은 여러 강좌를 듣고, 강좌 하나에는 여러 회원이 있습니다. 어느 한쪽에 FK를 두면 한 칸에 여러 값을 적어야 하므로(1NF 위반), 둘 사이에 중간 테이블 enrollments를 둡니다. 한 행이 "누가, 어떤 강좌를, 몇 월에" 신청했다는 기록

``` sql

CREATE TABLE enrollments (
    member_id   INT         NOT NULL REFERENCES members (member_id),
    course_id   INT         NOT NULL REFERENCES courses (course_id),
    enroll_month        CHAR(7)     NOT NULL,
    status      VARCHAR(10) NOT NULL,
    pay_amount INT,
    PRIMARY KEY (member_id, course_id, enroll_month)
);

INSERT INTO enrollments (member_id, course_id, enroll_month, status, pay_amount)
VALUES (1, 1, '2026-09', '수료', 70000);
INSERT INTO enrollments (member_id, course_id, enroll_month, status, pay_amount)
VALUES (2, 2, '2026-09', '수료', 50000);

```
